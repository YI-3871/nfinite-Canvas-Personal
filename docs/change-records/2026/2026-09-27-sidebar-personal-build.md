## 用户需求与修改前现象

用户希望把画布作为个人长期项目维护，需要通俗解释和适度而非企业级流程。侧栏存在原项目 GitHub 主页、作者名称及社媒链接，切换 GitHub 账号后仍显示。用户明确要求先去掉这些展示，并在询问后确认关闭原项目更新入口，以免覆盖个人定制。

## 根本原因

- 这些内容直接写在 `static/index.html`，不是 GitHub 登录状态或账户头像。修改远程仓库配置不会改变页面链接。
- 主页面原本在 DOMContentLoaded 调用 `checkForUpdates`，支持从 GitHub/ModelScope 下载上游代码。后端更新路径可以替换 `main.py`、`VERSION` 和整个 `static`。
- 原项目 LICENSE 要求衍生软件保留来源作者署名，因此把来源清晰保留在 README，不删除许可证或历史归属。

## 实施方案

移除主侧栏宣传 DOM 及专用作者样式，移除主页面更新弹窗和相关脚本。版本标签变为不可点击的显示项，页面加载仅通过 `/api/app-info` 读取本地版本，忽略响应中的上游地址。语言切换刷新版本说明。请求失败、HTTP 非成功或 JSON 无效时静默保留占位版本，不影响其他导航。

本次关闭的是主页面入口及其调用，不是后端更新 API 的安全封锁；后端旧模块和部分未使用的更新样式仍保留，避免扩大修改范围。
