# Infinite Canvas 双目录维护策略

## 目录职责

| 目录 | 角色 | 默认允许的操作 |
| --- | --- | --- |
| `E:\huabu初版\Infinite-Canvas-main` | 稳定初始包 | 只读检查、复制；只有用户确认开发版测试通过后才同步已验证文件 |
| `E:\huabu开发版\Infinite-Canvas-main` | 日常开发版 | 诊断、修改、测试、记录、Git 提交和后续功能开发 |

初始包保留 Python 3.10 本体，但不保留后来安装到 `python\Lib\site-packages` 的第三方依赖。开发版保留当前可运行依赖，用于后续测试。

## 固定工作流

1. 后续任务必须先确认当前工作目录是开发版。
2. 在开发版读取 `AGENTS.md`、相关变更记录和 ADR，再检查 Git 工作树。
3. 使用 `codex/` 分支完成修改、测试和记录，不碰用户已有未提交内容。
4. 向用户报告验证结果和未验证内容，等待用户实际使用测试。
5. 只有用户明确确认“测试通过，可以同步初始包”后，才把本次精确文件清单同步到初始包。
6. 同步后再次比较文件哈希，并在开发版新增同步记录；初始包不接收运行数据。

## 永不自动同步的内容

- `.git/` 和任何分支、标签、凭据配置。
- `API/.env`、API Key、Token、Cookie、私钥。
- `data/`、`assets/`、`output/`、`history.json` 和 SQLite 日志。
- `python\Lib/`、`python\Scripts/`、`__pycache__/`、`*.pyc` 和预览缓存。
- 用户素材、生成结果、调试包和其他机器本地状态。

## 同步回初始包的准入条件

- 用户明确授权同步。
- 相关自动测试、语法检查、浏览器联调和 `git diff --check` 已按风险完成。
- 变更记录列出全部文件、行为变化、兼容性、已知限制和回退点。
- 精确暂存区没有夹带无关文件或敏感信息。
- 同步只覆盖变更记录列出的源码、测试和文档；不得整目录覆盖。

- 7 张 PNG 原本位于 `assets\output`，被 `.gitignore` 排除且未进入 Git；删除后不能从仓库历史恢复。
- 若开发版损坏，重新从初始包复制代码后再安装依赖；不要反向整目录覆盖初始包。
- 若已同步代码出现问题，依据开发版 Git 提交和变更记录执行可审计回退，再经用户确认同步回初始包。
